## Task brief · pgvector-go

**Problem**

sqlate's migrator now manages extensions, and sqlate's `postgres/pgvector` names pgvector's
metrics. go-database has neither yet:

- admin's `Status` reports only migration sets. It says ready while `Verify` fails on an
  extension.
- No go-database module resolves a configured metric or shows how an application uses pgvector-go.
- go-database has no live tests.

capstone-athena needs all three before it stores embeddings.

**Behaviors**

1. go-database's base module requires sqlate v0.8.0, claude-plugins 0.24.0 and mise-action
   v5.3.0, and its currency reports none of them trailing.
2. `admin.Status` gains `Extensions` (`extensions` in JSON). It has one entry per declaration, in
   declared order, each with name, removed, installed, default and pending. The list is empty,
   never nil, when no extension is declared.
3. `Status.Ready` is false when any declaration doesn't match the database: one pending, one the
   image doesn't offer, or one with no update path to the default. The service's readiness follows
   `Status` as it does for sets.
4. `ErrExtensionUnavailable` and `ErrNoUpdatePath`, from `Start`, `Verify` and the schema verbs,
   wrap in `admin.ErrConflict` with the migrate sentinel still in the chain, and mark the service
   not ready.
5. Before `Start` applies, it logs each pending extension as `extension pending; applying`, with
   its name and its installed and default versions, beside the pending sets.
6. A new module, `github.com/standards-lab/go-database/postgres/pgvector`, with its own changelog
   and `doc.go`:
   - Its package exports `ParseMetric(name string) (Metric, error)` and a sentinel
     `ErrUnknownMetric`.
   - `Metric` is sqlate's `pgvector.Metric`; the package declares no type of its own.
   - `ParseMetric` matches a name exactly against sqlate's `pgvector.Metrics()`. An unknown name
     returns an error that unwraps to `ErrUnknownMetric` and names it, with no I/O.
   - The package imports only the standard library and sqlate's `postgres/pgvector`. pgvector-go
     v0.4.1, go-database v0.13.0 and sqlate's `postgres` v0.9.0 are required for the tests only.
7. The package doc shows pgvector-go used directly, in the packages the application's design
   declares: `pgvector.NewVector` for a parameter, and `sql.Null[pgvector.Vector]` with `Slice()`
   for a nullable column. Domain types hold `[]float32`. The doc also shows a metric resolved from
   configuration with `ParseMetric`.
8. go-database has a compose stack:
   - It copies sqlate's canonical PostgreSQL image: `postgres:19.0-alpine`, with pgvector built
     from source and pinned by `ARG PGVECTOR_VERSION`.
   - It publishes `127.0.0.1:${POSTGRES_PORT:-5438}` and keeps its data on tmpfs.
   - `mise run db:up` builds and starts it and waits until it is healthy, and `db:down` stops it.
9. go-database's currency is sqlate's script. It checks the requirements, Go, tools, actions,
   image lines, the Dockerfile's `FROM` line and its source ARGs. It keeps go-database's comment on
   failing scans, and mise installs crane for the image checks.
10. The module's integration tier sits behind the `integration` tag and uses `GO_DATABASE_DSN` and
    `pgtest`:
    - `admin.Start` with `vector` declared activates it. `Status` then reports it installed at the
      image's default, not pending, and `Ready`.
    - A `vector` column round-trips `pgvector.NewVector` values, and a NULL, through
      `sql.Null[pgvector.Vector]`, over pgx's `database/sql` adapter.
    - Each metric's operator orders a nearest-neighbor query.
11. `mise run integration` runs the tier against a running stack. `mise run acceptance` brings the
    stack up, runs the tier, brings the stack down whatever the result, and prints the stack's log
    on failure.
12. The check, build, tidy, test and lint tasks include the new module, and go.work uses it. The
    check vets, fixes and lints the `integration`-tagged suite with its tag.
13. The README and the standards file name the module and its dependency line. The README says the
    integration tier runs locally only, through `mise run acceptance`.
14. The base changelog records `v0.13.0`: the sqlate requirement, `Status.Extensions`, the
    readiness rule and the error mapping. The module's changelog records `v0.1.0`.

**Test seams**
- `admin.Service` over sqlate's `sqltest`, with a dialect that implements
  `migrate.ExtensionCatalog` (behaviors 2–5).
- `ParseMetric`'s unit tests (behavior 6).
- `mise run currency`, and `mise run db:up` offering `vector` (behaviors 1, 8 and 9).
- `pgtest.MigratedWith` and `admin.New` in the module's integration tier, through
  `mise run acceptance` (behavior 10).

**Slices**
1. Upgrade go-database: sqlate v0.8.0, claude-plugins 0.24.0, mise-action v5.3.0. Done when
   currency exits 0 with the current script and the check passes.
2. admin's extension status: `Status.Extensions`, the readiness rule, the error mapping and the
   pending log, with unit tests; admin's doc.go and the base changelog's Unreleased entry. Done
   when the check passes.
3. The module and `ParseMetric`: the package, its unit tests, its doc with the pgvector-go usage,
   its changelog; go.work, `GO_MODULES`, the README and the standards file. Done when the check
   passes with the module listed.
4. The compose stack and currency: the copied Dockerfile, the compose files, `db:up`/`db:down`;
   sqlate's currency script with the comment carried over, and crane. Done when `mise run db:up`
   offers `vector` 0.8.7, currency exits 0, and lowering the ARG default by hand makes currency
   report pgvector trailing.
5. The live proof: the integration tier and the module's test requirements, with go-database
   bridged by a `replace` until `v0.13.0` is tagged; the `integration` and `acceptance` tasks, the
   check's tagged pass, and the README's local-only note. Done when `mise run acceptance` passes
   and the check passes.

**Out of scope**

- Wrapping pgvector-go's types, a `migrate.Extension` helper, SQL generation, a space registry, and
  distance or score conversion.
- pgvector-go's pgx module and an AfterConnect hook.
- `halfvec` and `sparsevec` helpers.
- An integration job in CI, and changes to the CI workflow.
- Upgrading the ARG in `mise run upgrade`.
- A `postgres` release, and any change to sqlate.

**Door**

One-way for both tags. Once `v0.13.0` is pushed, `Status.Extensions`, its JSON shape, the
readiness rule and the `ErrConflict` mapping are public. Once `postgres/pgvector/v0.1.0` is pushed,
`ParseMetric`, `ErrUnknownMetric` and the module path are public. The compose stack, the currency
script and the tests stay two-way.

**Release**

`v0.13.0`, then `postgres/pgvector/v0.1.0`, whose `go.mod` pins go-database `v0.13.0` in place of
the `replace`.

## Decisions

- plan: The image is an extension's sole version source: `postgres:19.0-alpine` with each extension
  built from source, pgvector pinned by `ARG PGVECTOR_VERSION`. Rejected: pgvector/pgvector's
  Debian images, PGDG on Debian, and a version declared in Go.
- plan: Shipped migration sets declare no extensions; only the application does.
- plan: go-database's module is `go-database/postgres/pgvector`. It uses pgvector-go's root module
  over `database/sql` and depends on `sqlate/postgres/pgvector`'s metric table.
- extension-stage: A removed declaration still installed is pending: `Verify` unwraps to
  `ErrPending` and `Extensions` marks it pending, so `admin.Status` reports it not `Ready`.
- sqlint-extensions: rejected sqlfluff and squawk, which lint against a fixed dialect and can't
  read a module's exported deny list.
- pgvector-sql: go-database copies sqlate's canonical `compose/postgres/Dockerfile` and the ARG
  check in `scripts/currency.sh`.
- pgvector-sql: an extension module's live proof runs in its own module's integration tier, with
  that module requiring `postgres` for `pgtest`. The engine module never requires its extensions.
- pgvector-go: Applications use pgvector-go's root module directly, in the packages their design
  declares: `pgvector.NewVector` in, `sql.Null[pgvector.Vector]` and `Slice()` out; domain types
  hold `[]float32`. go-database wraps no vector type. Rejected: `Param`/`Dest` wrappers over
  `[]float32` (indirection the import rule already makes unnecessary), and a `migrate.Extension`
  helper.
- pgvector-go: go-database's `postgres/pgvector` holds `ParseMetric`, returning sqlate's
  `pgvector.Metric`, and the integration tier; its package needs pgvector-go only in tests.
- pgvector-go: `admin.Status.Ready` is false on any extension mismatch (pending, unavailable, no
  update path); admin wraps `ErrExtensionUnavailable` and `ErrNoUpdatePath` in `ErrConflict`.
- pgvector-go: go-database's integration tier uses `GO_DATABASE_DSN` on 5438 and a tmpfs stack,
  runs locally only, and the check vets, fixes and lints it with its tag.
